# Scope와 SSR

`createScope`와 `createStateFactory`는 `@ilokesto/state`에서 가져옵니다.
두 API는 프레임워크 런타임을 import하지 않습니다. Factory 정의는 모듈에서
공유할 수 있지만 store와 owner는 각 요청 안에서 생성하세요. 사용자 데이터가
담긴 mutable 서버 singleton을 export하지 마세요.

## 소유권

```ts
import { createScope, createStore } from '@ilokesto/state';

const owner = createScope();
const counter = owner.create(() => createStore({ count: 1 }));
const consumer = createScope();
const borrowed = consumer.borrow(counter);

consumer.dispose(); // counter는 해제하지 않습니다.
borrowed.update(state => ({ count: state.count + 1 }));
owner.dispose(); // counter에 등록된 middleware cleanup을 실행합니다.
```

`scope.create(factory)`는 동기적으로 소유권을 얻으며 middleware capability를
포함한 정확한 store 타입을 유지합니다. Callback은 이 owner의 store를 생성해야
합니다. 다른 scope 소유의 store를 반환하면 그 owner가 이미 해제되었더라도
오류가 발생합니다. 같은 scope에서 같은 store를 다시 반환해도 cleanup은
중복되지 않습니다. `borrow(store)`는 `ReadableStore`도 허용하며 소유권 없이
동일한 객체를 반환합니다.

`scope.dispose()`는 먼저 scope를 닫고, 생성 역순으로 소유한 store의 middleware
cleanup을 모두 실행합니다. 실패는 `AggregateError`로 모으며 반복 호출은
안전합니다. `scope.disposed`로 닫힘 여부를 확인합니다. 닫힌 뒤 생성하거나
빌리면 오류가 발생합니다. Factory 실패만으로 scope가 닫히지는 않습니다.
Factory가 자기 scope를 닫으면 반환된 store를 해제한 뒤 생성 오류를 던집니다.

해제 범위는 `dispose(store)`와 같습니다. 등록된 middleware 자원만 해제하며
소비자가 직접 만든 구독을 제거하거나 store를 freeze하거나 기존 참조를
무효화하지 않습니다. 먼저 소비자를 unmount하거나 unsubscribe한 다음 owner를
해제하세요. 저장이 필요하면 dispose 전에 persistence `flush()`를 명시적으로
기다리세요. 빌린 scope를 닫아도 프레임워크 구독이나 원래 store는 해제되지
않습니다.

## 검증된 하나의 초기 상태

```ts
// counter.ts -- 서버와 클라이언트가 공유합니다.
import { createStateFactory } from '@ilokesto/state';

export const counterFactory = createStateFactory({
  decode(input: unknown): { count: number; label: string } {
    if (
      typeof input !== 'object' || input === null ||
      !('count' in input) || typeof input.count !== 'number' ||
      !Number.isSafeInteger(input.count) || input.count < 0 ||
      !('label' in input) || typeof input.label !== 'string'
    ) throw new TypeError('Invalid counter');
    return { count: input.count, label: input.label };
  },
});
```

Decoder는 필수이며 유효하지 않은 도메인 데이터에 오류를 던져야 합니다.
난수 기본값, 현재 시간, 브라우저 전역, 요청과 무관한 mutable cache에 의존하지
않는 결정적 함수여야 합니다. `create(input: unknown)`와
`hydrate(serialized: string)`에서 모두 실행됩니다. 이미 decode한 데이터를 다시
decode하면 property 순서를 포함한 canonical JSON 표현을 유지해야 합니다.
Hydration 중 decoder가 전송 값을 바꾸면 불일치하는 클라이언트 store를 만들기
전에 거부합니다. 검증된 결과는 JSON 데이터로
복사하므로 decoder가 캐시한 객체를 반환해도 중첩 상태가 요청 사이에 공유되지
않습니다. 호출마다 새 store를 생성합니다. 선택적인 `create(initialState)`
callback으로 middleware store를 만들 수 있습니다. 전달받은 초기 상태를
유지하고 새 인스턴스를 반환해야 합니다. 같은 state factory에서 이전에 반환한
인스턴스를 다시 반환하면 오류가 발생합니다.

```ts
import { createScope } from '@ilokesto/state';
import { counterFactory } from './counter';

export function createRequestPayload(input: unknown): string {
  const requestScope = createScope();
  try {
    const counter = requestScope.create(() => counterFactory.create(input));
    return counterFactory.serialize(counter);
  } finally {
    requestScope.dispose();
  }
}

export function createClientState(payload: string) {
  const scope = createScope();
  const counter = scope.create(() => counterFactory.hydrate(payload));
  return { scope, counter };
}
```

`serialize(store: ReadableStore<State>): string`은 `getState()`가 아니라
`getInitialState()`를 전달합니다. Envelope는 `{ "version": 1, "state": ... }`이며
version은 persistence schema가 아닌 전송 형식의 버전입니다. React의 기존 서버
snapshot은 여전히 초기 상태를 선택하고 나머지 adapter는 현재 상태를 읽습니다.
모든 프레임워크에서 HTML을 일치시키려면 요청 데이터 로딩을 **store 생성 전에**
완료하고 생성, 서버 렌더링, 최초 클라이언트 hydration 사이에 쓰지 마세요.
나중 snapshot을 전달하려면 그 값으로 새 요청 store를 만든 후 렌더링하세요.
기존 store의 초기 상태를 바꾸지 않습니다.

`hydrate`는 envelope를 검증하고 도메인 decoder를 호출한 다음 클라이언트 store를
생성합니다. 기존 store에 쓰거나 persistence migration을 실행하거나 storage에
접근하거나 `persist.rehydrate()`를 호출하지 않습니다. Persistence를 함께
사용하면 먼저 서버 payload로 DOM을 hydrate하고, 이후 애플리케이션 충돌 정책에
맞게 `store.persist.rehydrate()`를 명시적으로 호출하세요.
[Persistence migration](/ko/state/advanced/persist-migrations)을 참고하세요.

## 전송 경계

JSON 데이터만 지원합니다. null, boolean, string, 음수 0을 제외한 유한 number,
dense array, enumerable data property만 가진 plain object가 해당합니다. Date,
Map, Set, 함수, undefined, bigint, symbol, accessor, sparse array, 배열의 추가
property, class instance, cycle, `__proto__`/`constructor`/`prototype` property는
암묵적으로 변환하지 않고 거부합니다. 복잡한 도메인 값은 애플리케이션에서
명시적인 JSON 필드로 인코딩하세요.

각 serialization/parse 경계의 한도는 UTF-16 code unit 1,000,000개, 방문 값
100,000개, 중첩 깊이 64입니다. Envelope도 이 한도에 포함됩니다. Escape한
출력의 길이도 다시 검사합니다. 잘못된 입력과 미지원 형태는 `TypeError` 또는
JSON parser의 `SyntaxError`를 발생시키고 decoder 예외는 그대로 전달합니다.
검증 실패를 기본 상태로 바꾸는 fallback은 없습니다.

직렬화한 `<`, `>`, `&`, U+2028, U+2029는 escape하므로 반환 문자열을
`application/json` script element의 text로 사용할 수 있습니다. `eval` 대신
`textContent`로 읽고 전체 문자열을 `hydrate`에 전달하세요. HTML attribute나
실행 가능한 JavaScript 안에 삽입하지 마세요. Payload는 브라우저에 공개되므로
사용자가 볼 수 있는 필드만 전달합니다. 검증은 권한 검사나 유효한 값을 바꾸는
공격에 대한 인증이 아닙니다. 서버에서 권한을 별도로 검증하세요.

## 프레임워크 검증 근거와 lifecycle 경계

`e2e/ssr.browser.mjs`는 실제 Node 서버 renderer, 서로 다른 상태를 가진 두 개의
동시 요청, Chromium client hydration을 사용합니다. 서버/클라이언트 text 일치,
실제 서버 DOM node 재사용, hydration 후 갱신, borrowed ownership, unmount 후
구독 0개, 다른 selector로 두 번째 mount와 추가 갱신을 확인합니다.
`e2e/selectors.browser.mjs`는 custom equality와 React selector/equality 교체를
별도로 확인합니다.

| Adapter | 서버/클라이언트 경로 | Selector 교체 | 소비자 cleanup |
| --- | --- | --- | --- |
| React 19 | `renderToString` / `hydrateRoot`, 클라이언트 StrictMode | Remount 없이 다음 render에서 selector/equality 교체 가능 | Root unmount로 구독 해제; StrictMode는 store를 소유하지 않음 |
| Vue 3 | `renderToString(createSSRApp(...))` / `createSSRApp().mount(...)` | Composable이 selector를 캡처하므로 새 소비자 scope/component 생성 | Component/effect scope 종료 |
| Angular 21 | `renderApplication`, `provideServerRendering`, `provideClientHydration` / `bootstrapApplication` | Signal이 selector를 캡처하므로 새 injection lifecycle에서 생성 | 실제 application destruction의 `DestroyRef` |
| Svelte 5 | 컴파일한 서버 `render` / 클라이언트 `hydrate` | Selected readable이 selector를 캡처하므로 새 readable을 만들고 구독 | 컴파일한 component unmount가 unsubscribe |
| Solid 1 | Hydration key를 사용하는 `renderToString` / `hydrate` | Accessor가 selector를 캡처하므로 새 reactive owner 생성 | Owner disposal |

테스트 범위는 설치된 위 major version과 동기 초기 content입니다. 모든 peer
version 조합, streaming boundary, Suspense, navigation, 프레임워크별 배포를
검증한 것은 아닙니다. 서버 scope는 `finally`에서 해제합니다. 서버 소비자
lifecycle은 프레임워크 renderer와 garbage collection이 담당합니다. State
scope가 프레임워크의 서버 cleanup 동작을 대체하지 않습니다. 전역 요청 context,
AsyncLocalStorage, 프레임워크 provider를 자동 설치하지 않습니다.

React application owner는 반복 실행될 수 있는 effect 밖에서 생성하세요.
StrictMode effect cleanup이 반복 setup에서 재사용할 scope를 해제해서는 안
됩니다. Component는 application store를 빌리고, 실제 application 종료에서
root를 unmount한 후 owner를 닫습니다.

## Next.js App Router 레시피

아래는 애플리케이션 레시피입니다. 새로운 package entrypoint나
Next/Nuxt/SvelteKit 배포를 검증했다는 의미가 아닙니다. 기존 프로젝트에서 위의
공유 `counter.ts`를 사용하세요. 예제는 외부 자원이 없는 plain store를 사용합니다.

```tsx
// app/page.tsx
import { createScope } from '@ilokesto/state';
import { counterFactory } from './counter';
import { Counter } from './Counter';

export default function Page() {
  const scope = createScope();
  try {
    const store = scope.create(() => counterFactory.create({ count: 1, label: 'loaded' }));
    const payload = counterFactory.serialize(store);
    return <Counter key={payload} payload={payload} />;
  } finally {
    scope.dispose();
  }
}
```

```tsx
// app/Counter.tsx
'use client';
import { useMemo, useState } from 'react';
import { bind } from '@ilokesto/state/react';
import { counterFactory } from './counter';

export function Counter({ payload }: { payload: string }) {
  const [store] = useState(() => counterFactory.hydrate(payload));
  const useCounter = useMemo(() => bind(store), [store]);
  const [count] = useCounter(state => state.count);
  return <button onClick={() => store.update(state => ({ ...state, count: state.count + 1 }))}>
    {count}
  </button>;
}
```

직렬화된 prop으로 같은 검증 값을 가진 별도의 서버/클라이언트 store를
초기화합니다. 새 payload가 오면 `key`가 의도적으로 client boundary를
초기화합니다. 반복 render initializer에서 자원 소유 middleware를 할당하지
마세요. 그런 경우에는 별도로 관리하는 application lifecycle을 사용하세요.

## Nuxt 레시피

```ts
// plugins/counter.ts -- Nuxt app/요청마다 생성하는 universal plugin
import { createScope } from '@ilokesto/state';
import { bind } from '@ilokesto/state/vue';
import { counterFactory } from '~/counter';

export default defineNuxtPlugin(nuxtApp => {
  const scope = createScope();
  const payload = useState('counter:ssr', () => {
    const store = scope.create(() => counterFactory.create({ count: 1, label: 'loaded' }));
    return counterFactory.serialize(store);
  });
  const store = scope.create(() => counterFactory.hydrate(payload.value));
  if (import.meta.server) nuxtApp.hook('app:rendered', () => scope.dispose());
  else nuxtApp.vueApp.onUnmount(() => scope.dispose());
  return { provide: { counter: bind(store) } };
});
```

```vue
<!-- pages/index.vue -->
<script setup lang="ts">
const { $counter } = useNuxtApp();
const { state: count, setState } = $counter(state => state.count);
</script>
<template>
  <button @click="setState(state => ({ ...state, count: state.count + 1 }))">
    {{ count }}
  </button>
</template>
```

Nuxt 자체 payload 경로로 문자열을 전달합니다. Factory만 공유하고 plugin은
요청별로 유지하세요. 실패할 수 있는 자원 소유 middleware를 쓰는 애플리케이션은
`app:rendered`뿐 아니라 프레임워크의 render error/abort 경로에서도 요청 owner를
닫아야 합니다.

## SvelteKit 레시피

```ts
// src/routes/+page.server.ts
import { createScope } from '@ilokesto/state';
import { counterFactory } from '$lib/counter';

export function load() {
  const scope = createScope();
  try {
    const store = scope.create(() => counterFactory.create({ count: 1, label: 'loaded' }));
    return { payload: counterFactory.serialize(store) };
  } finally {
    scope.dispose();
  }
}
```

```svelte
<!-- src/routes/+page.svelte -->
<script lang="ts">
  import Counter from '$lib/Counter.svelte';
  let { data } = $props();
</script>

{#key data.payload}
  <Counter payload={data.payload} />
{/key}
```

```svelte
<!-- src/lib/Counter.svelte -->
<script lang="ts">
  import { onDestroy } from 'svelte';
  import { createScope } from '@ilokesto/state';
  import { bind } from '@ilokesto/state/svelte';
  import { counterFactory } from './counter';
  let { payload }: { payload: string } = $props();
  const scope = createScope();
  const store = scope.create(() => counterFactory.hydrate(payload));
  const counter = bind(store);
  const count = counter.select(state => state.count);
  onDestroy(() => scope.dispose());
</script>

<button onclick={() => counter.update(state => ({ ...state, count: state.count + 1 }))}>
  {$count}
</button>
```

Loader data가 바뀌면 keyed component가 의도적으로 상태를 다시 만듭니다.
Svelte는 readable 구독을 소유하고 component는 store를 소유합니다. 어느 쪽도
서버 모듈 전역 변수에 두지 마세요.
