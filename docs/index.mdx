# State

`@ilokesto/state` connects `@ilokesto/store` to framework lifecycles. It gives each framework a small `create()` adapter while keeping the underlying state model framework-neutral.

```tsx lineNumbers
import { create } from '@ilokesto/state/react';

const useCounter = create({ count: 0 });

function Counter() {
  const [count, setCounter] = useCounter((state) => state.count);
  return <button onClick={() => setCounter((state) => ({ count: state.count + 1 }))}>{count}</button>;
}
```

Use this package when you want one small store model with adapter-specific return shapes for React, Vue, Svelte, Solid, or Angular.

## Install

```package-install
@ilokesto/state
```

Install the framework peer you use, such as `react`, `vue`, `svelte`, `solid-js`, or `@angular/core`. Install `immer` only when you use `adaptor` from `@ilokesto/state/adaptor`.


## Choose State or Store

Choose `@ilokesto/state` when framework components should react to shared state, or when you need reducers, persistence, validation, DevTools, history, or timed middleware. Choose the smaller [`@ilokesto/store`](/en/store) when plain TypeScript code should own a value and you are prepared to connect subscriptions and cleanup yourself.

State does not replace `@ilokesto/store`; it creates or wraps the same store model. It is not an async server cache, a normalized entity layer, or a framework tutorial.

## Version and source basis

The installable package manifest is `@ilokesto/state@1.0.4`. The landing example and quick start use the established framework-subpath `create()` API. This documentation was audited against the workspace source at commit `bb26d48`. Root `createStore`/`createReducer`, framework `bind`/`bindReducer`, and the new notification foundation are pending-major workspace APIs recorded in Changesets; use the [next-major migration guide](/en/state/advanced/migration) rather than assuming they are present in the current npm version.
