# debounce

`debounce`는 기존 동작을 유지하여 **첫 호출에서 시작하는 고정 window**에 update를 모읍니다. 이후 호출은 window를 다시 시작하지 않습니다. 마지막 호출 기준의 quiet window가 필요하면 `{ mode: 'quiet' }`를 사용하세요.

## Signature

```ts lineNumbers
debounce(wait?: number, options?: DebounceOptions): DebouncePipeMiddleware
```

`wait`의 단위는 밀리초이며 기본값은 `300`입니다. 전달했다면 유한한 0 이상의 숫자여야 하며 `0`도 유효합니다. 잘못된 wait 값은 middleware 또는 timer를 설정하기 전에 `RangeError`를 던집니다.

| 옵션 | 기본값 | 의미 |
| --- | --- | --- |
| `mode` | `'fixed'` | `'quiet'`는 호출마다 마감 시각을 다시 설정합니다. |
| `leading` | `false` | 첫 호출을 즉시 commit하고 wait window를 엽니다. |
| `trailing` | `true` | 이후 호출을 누적하여 window가 끝날 때 commit합니다. |

두 edge가 모두 `false`이면 `TypeError`를 던집니다. 둘 다 켜도 leading 호출 하나를 trailing에서 반복하지 않습니다. Quiet mode에서는 드롭된 호출도 leading-only cooldown을 연장합니다. 등록된 middleware는 `DebounceControls`를 추가하며 결과 store는 `DebounceStore<State>`로 표현합니다.

## 예제

```ts lineNumbers
import { debounce } from '@ilokesto/state/middleware';
import { pipe } from '@ilokesto/state/utils';

const store = pipe
  .use(debounce(250))
  .create({ query: '' });

store.setState({ query: 'i' });
store.setState({ query: 'il' });
store.setState({ query: 'ilo' });
```

## Control

```ts
const search = pipe.use(debounce(250, { mode: 'quiet' })).create({ query: '' });
search.set({ query: 'ilokesto' });
search.debounce.pending(); // true
search.debounce.flush(); // 동기 commit 후 window를 다시 엽니다
search.debounce.cancel(); // updater를 평가하지 않고 대기 작업을 버립니다
```

변경할 수 없는 `store.debounce` namespace는 `TimerControls`인 `flush(): void`, `cancel(): void`, `pending(): boolean`을 제공합니다. `pending()`은 leading-only cooldown이 아닌 대기 update를 보고합니다. Flush와 cancel은 대기 update가 없어도 window를 다시 엽니다. 기존 `debounce` property가 있으면 덮어쓰지 않고 setup을 거부합니다.

Flush는 해당 timer의 작업만 뒤쪽 middleware로 전달하며, 뒤의 다른 timer는 여전히 지연할 수 있습니다. 전체 middleware chain을 다시 실행하지 않습니다. 최종 누적 candidate를 검증하려면 validation을 timer 뒤에 두세요. 앞에 두면 개별 요청을 검증합니다.

## persist와 함께 사용하기

`debounce`는 `persist`보다 먼저 선언하세요. 영속화는 최초 업데이트 요청이 아닌 실제 지연된 commit을 관찰합니다.

```ts lineNumbers
import { debounce, jsonStorage, persist } from '@ilokesto/state/middleware';
import { pipe } from '@ilokesto/state/utils';

type SearchState = { readonly query: string };

const decodeSearch = (value: unknown): SearchState | null => {
  if (typeof value !== 'object' || value === null || !('query' in value)) return null;
  return typeof value.query === 'string' ? { query: value.query } : null;
};

const store = pipe
  .use(debounce(250))
  .use(persist({ key: 'search', storage: jsonStorage(() => window.localStorage), decode: decodeSearch }))
  .create<SearchState>({ query: '' });

await store.persist.rehydrate();
```

반대 선언 순서는 계속 `MIDDLEWARE_ORDER`로 거부됩니다. 복원은 debounce를 기다리지 않고 즉시 commit합니다. `store.persist.flush()`는 commit된 저장 대상을 기다릴 뿐 timer를 실행하지 않습니다. Commit과 저장을 모두 마치려면 `store.debounce.flush()` 이후 `store.persist.flush()`를 기다리세요.

## Function update

Function update는 flush 시점의 최신 commit state에서 순서대로 평가합니다. Value update는 누적 값을 교체하고 이후 updater는 교체된 값에서 계속합니다. 뒤의 value가 결과를 교체하더라도 앞의 updater는 실행합니다. Cancel은 대기 updater를 평가하지 않습니다.

평가 전에 batch를 분리합니다. Updater나 subscriber의 재진입 쓰기는 새 window를 만들고 기존 flush가 throw해도 유지됩니다. Updater 오류는 분리된 batch를 commit 없이 버립니다. 동기 `flush()`는 오류를 전파하고 timer 만료 시에는 host timer callback으로 보고합니다. Subscriber 오류는 이미 commit된 값을 rollback하지 않습니다. Leading 오류 후 cooldown은 만료, flush 또는 cancel까지 유지됩니다.

## Timing 주의점

Trailing commit 전까지 `getState()`는 이전 commit state를 반환합니다. 모든 쓰기를 즉시 관찰해야 하는 state에는 trailing debounce를 쓰지 마세요.

`history()`는 어느 선언 순서에서도 함께 사용할 수 있으며 예약 요청이 아닌 실제 commit을 기록합니다. Undo/redo는 history entry가 없어도 모든 pending timer 작업을 평가 없이 취소한 뒤 validation을 거쳐 동기 replay합니다. 재진입 사용자 쓰기는 계속 timer를 따릅니다. Group과 pause는 commit 시점의 범위를 적용하므로 지연 작업을 그룹에 넣으려면 동기 group 안에서 flush하세요.

## Cleanup

`debounce`는 대기 중인 timer를 소유합니다. Store가 더 이상 필요 없으면 `@ilokesto/state/middleware`의 `dispose(store)`를 호출해 취소하세요. Disposal은 해당 store에만 적용되며 반복 호출해도 안전합니다. Cleanup 하나가 실패해도 등록된 모든 cleanup을 시도하며, 하나라도 실패하면 각 원래 thrown value가 담긴 `AggregateError`를 throw합니다.

Disposal은 updater를 평가 중인 trailing batch도 무효화하여 이후 commit을 막습니다. Leading 호출은 action을 먼저 평가하지 않고 즉시 전달합니다. Store는 재사용할 수 있고 이후 쓰기는 새 timer window를 시작합니다. Cancel이나 disposal은 이미 commit된 값을 되돌리지 않습니다.
