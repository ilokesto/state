# persist

`persist`는 상태 commit은 동기로 유지하면서 비동기 복원, 저장, 오류를 관리합니다. `key`, `storage` 팩토리, 필수 `decode` 함수를 설정하세요. `pipe.use(...)`에 등록한 뒤 `.create(initialState)`로 스토어를 만듭니다.

헬퍼, 미들웨어, 스토어 생성 시에는 저장소 I/O나 `window`, `document`, `indexedDB` 접근이 없습니다. `await store.persist.rehydrate()`로 복원을 명시적으로 시작하세요.

## JSON 상태 저장과 복원

다음 완전한 예제를 브라우저 모듈에서 실행하면 이전 테마를 복원하고 어두운 테마로 변경한 뒤 저장 완료를 기다립니다.

```ts lineNumbers
import { dispose, jsonStorage, persist } from '@ilokesto/state/middleware';
import { pipe } from '@ilokesto/state/utils';

type ThemeState = { theme: 'light' | 'dark' };

const decodeTheme = (value: unknown): ThemeState | null => {
  if (typeof value !== 'object' || value === null || !('theme' in value)) return null;
  return value.theme === 'light' || value.theme === 'dark' ? { theme: value.theme } : null;
};

const store = pipe
  .use(persist({
    key: 'theme',
    storage: jsonStorage(() => window.localStorage),
    decode: decodeTheme,
  }))
  .create<ThemeState>({ theme: 'light' });

try {
  await store.persist.rehydrate();
  store.setState({ theme: 'dark' });
  await store.persist.flush();
} finally {
  dispose(store);
}
```

호출부에서 거부된 작업을 처리하세요. `setState`는 동기로 commit하지만 저장소 반영 완료를 뜻하지 않습니다.

## 어댑터 선택

다음 헬퍼는 모두 `@ilokesto/state/middleware`에서 가져오며 저장소 팩토리를 반환합니다. 바깥에 `() =>`를 추가하지 말고 반환값을 직접 전달하세요.

| 저장소 | `storage` 옵션 | 지원 값 |
| --- | --- | --- |
| IndexedDB | `indexedDBStorage({ database: 'my-app-state' })` | structured clone 가능한 값 |
| localStorage | `jsonStorage(() => window.localStorage)` | JSON 값 |
| sessionStorage | `jsonStorage(() => window.sessionStorage)` | JSON 값 |
| 쿠키 | `cookieStorage({ path: '/' })` | 쿠키 크기 제한 내 JSON 값 |

`jsonStorage`는 브라우저 접근을 미루기 위해 getter를 받습니다. `jsonStorage(window.localStorage)`는 지원하지 않으며 SSR 중 브라우저 전역을 평가합니다. Web Storage 자체는 여전히 동기 I/O이며 영속화 완료와 오류 계약이 비동기입니다.

팩토리를 여러 스토어에서 재사용할 수 있습니다. 활성화마다 독립된 어댑터 인스턴스를 만들고 각 스토어의 수명 동안 재사용하며 매번 쓰기마다 생성하지 않습니다. 사용자 정의 팩토리에는 메타데이터가 필요 없습니다. 인스턴스는 `getItem`, `setItem`, `removeItem`, 필요하면 소유 리소스를 정리하는 `dispose`를 제공합니다. 팩토리 생성 실패는 재시도할 수 있으며 일반 I/O 실패로 이미 생성한 인스턴스를 교체하지 않습니다.

## 파일과 복합 자료형

IndexedDB는 `{ state, version }`을 structured clone으로 저장합니다. base64 변환 없이 `File`의 이름, 타입, 내용과 `Blob`, `Map`, `Set`, `Date`, `ArrayBuffer`를 보존합니다.

```ts lineNumbers
import { indexedDBStorage, persist } from '@ilokesto/state/middleware';
import { pipe } from '@ilokesto/state/utils';

type EditorState = { attachment: File | null; updatedAt: Date };

const decodeEditor = (value: unknown): EditorState | null => {
  if (typeof value !== 'object' || value === null) return null;
  if (!('attachment' in value) || (value.attachment !== null && !(value.attachment instanceof File))) return null;
  if (!('updatedAt' in value) || !(value.updatedAt instanceof Date)) return null;
  return { attachment: value.attachment, updatedAt: value.updatedAt };
};

const editor = pipe
  .use(persist({
    key: 'editor',
    storage: indexedDBStorage({ database: 'my-app-state' }),
    decode: decodeEditor,
  }))
  .create<EditorState>({ attachment: null, updatedAt: new Date(0) });

await editor.persist.rehydrate();
editor.setState({
  attachment: new File(['draft'], 'draft.txt', { type: 'text/plain' }),
  updatedAt: new Date(),
});
await editor.persist.flush();
```

이미지 미리보기의 `blob:` URL은 복원한 Blob으로 화면에서 다시 생성하고 필요 없을 때 해제하세요. URL 자체는 저장하지 않습니다. IndexedDB 성공은 request 성공이 아니라 **transaction complete** 기준입니다. 복제 불가능한 값, 용량 부족, 트랜잭션 실패는 저장을 거부합니다. localStorage로 자동 전환하지 않으며 JSON 어댑터는 이러한 네이티브 값을 보존하지 않습니다. `Date.toJSON()`은 문자열이 되고 `Map`, `Set`, `Blob` 등 지원하지 않는 값은 거부됩니다.

## 타입이 분리된 부분 저장

기존 전체 상태 설정은 그대로 사용할 수 있습니다. 일부만 저장하려면 `project(state: State): Persisted`, `decode(value: unknown): Persisted | null`, `restore(persisted: Persisted, current: State): State` 세 함수를 모두 제공하세요. 공개 설정 타입은 `ProjectedPersistConfig<State, Persisted, Steps>`이며 `Steps`의 기본값은 빈 migration 튜플입니다.

```ts lineNumbers
import { jsonStorage, persist } from '@ilokesto/state/middleware';
import { pipe } from '@ilokesto/state/utils';

type Preferences = { theme: 'light' | 'dark'; search: string };
type SavedPreferences = Pick<Preferences, 'theme'>;

const decode = (value: unknown): SavedPreferences | null => {
  if (typeof value !== 'object' || value === null || !('theme' in value)) return null;
  return value.theme === 'light' || value.theme === 'dark' ? { theme: value.theme } : null;
};

const preferences = pipe.use(persist({
  key: 'preferences',
  storage: jsonStorage(() => window.localStorage),
  project: (state: Preferences) => ({ theme: state.theme }),
  decode,
  restore: (saved, current) => ({ ...current, theme: saved.theme }),
  saveDebounceMs: 200,
})).create<Preferences>({ theme: 'light', search: '' });

await preferences.persist.rehydrate();
preferences.setState({ theme: 'dark', search: 'not persisted' });
await preferences.persist.flush();
```

저장 형식은 계속 `{ state: projectedValue, version }`입니다. `restore`가 유지할 필드를 명시적으로 선택하며 자동 얕은 병합이나 깊은 병합은 없습니다. 복원 시점의 현재 메모리 상태를 받고, 반환한 전체 상태는 등록된 상태 검증을 통과한 후 commit됩니다. decoder가 거부하면 `restore`는 실행하지 않습니다. migration은 저장 projection을 변환하며 migration 후 다시 저장할 때도 projection만 기록합니다.

`project`, `decode`, `restore`는 순수 함수로 작성하세요. projection은 동기 상태 commit 내부가 아니라 직렬 writer가 캡처한 commit을 저장할 때 실행됩니다. 최신 값으로 대체된 commit은 호출하지 않을 수 있습니다. projection 실패는 저장 대상을 대기 상태로 유지하고 `INVALID_DATA`를, restore 실패는 `VALIDATION`을 보고합니다. projection 변경으로 기존 레코드를 자동 변환하지 않습니다. 호환되는 decoder를 유지하거나 명시적인 데이터 migration을 추가하세요.

## 명시적인 문자열 codec

`@ilokesto/state/middleware`에서 공개하는 `PersistCodec`의 확정 시그니처는 다음과 같습니다.

```ts
type PersistCodec = {
  readonly serialize: (value: PersistedValue) => string;
  readonly deserialize: (text: string) => unknown;
};
```

`jsonStorage(getStorage, codec)` 또는 `cookieStorage({ codec, ...attributes })`로 전달합니다. codec은 전체 envelope의 문자열 직렬화를 담당합니다. 역직렬화 결과는 여전히 unknown이며 저장 형식/버전 검사, migration, `decode`를 통과해야 합니다. codec 예외는 원래 cause를 보존한 `STORAGE` 오류로 전달됩니다.

다음 codec은 `Date` 상태를 밀리초로 저장하고 네이티브 타입으로 복원합니다.

```ts lineNumbers
import type { PersistCodec } from '@ilokesto/state/middleware';

const dateCodec: PersistCodec = {
  serialize: (envelope) => {
    if (!(envelope.state instanceof Date)) throw new TypeError('Expected Date');
    return JSON.stringify({ state: envelope.state.getTime(), version: envelope.version });
  },
  deserialize: (text) => JSON.parse(text, (key, value: unknown) =>
    key === 'state' && typeof value === 'number' ? new Date(value) : value),
};
```

애플리케이션 decoder는 유효하지 않은 날짜도 거부해야 합니다. 중첩 데이터에서는 codec이 지원하는 구조를 명시적으로 처리해야 합니다. codec을 생략하면 기존 JSON 동작과 저장 바이트를 유지하며 `Date.toJSON()`도 계속 문자열이 됩니다. codec 변경에 따른 저장 형식 전환은 애플리케이션 책임이며 자동 migration이 아닙니다. IndexedDB는 이미 structured clone을 사용하므로 문자열 codec을 받거나 필요로 하지 않습니다.

## 수명주기 제어

| 제어 | 계약 |
| --- | --- |
| `await rehydrate()` | 명시적 복원. 동시 호출은 작업 공유, 성공 후 재호출은 아무 작업 없음, 실패 후 재시도 가능 |
| `await rehydrate({ conflict: 'keep-current' })` | 복원 충돌 시 현재 상태를 유지하고 저장 |
| `await rehydrate({ conflict: 'use-stored' })` | 검증한 저장값으로 현재 상태를 명시적으로 교체 |
| `await flush()` | 호출 시점의 저장 대상 완료 대기, 실패한 대기 쓰기 재시도 |
| `pause(): void` | 자동 저장 일시 중지. 상태 commit과 복원은 계속 실행 |
| `resume(): void` | 설정된 저장 debounce를 적용하여 최신 대기 값 자동 저장 재개 |
| `retry(): Promise<void>` | `flush()`와 동일한 보장으로 호출 시점 대상 재시도 |
| `await clearStorage()` | 이전 쓰기 뒤에 이 키만 삭제하고 메모리 상태는 유지 |
| `getStatus()` | 최신 불변 수명주기 상태 읽기 |
| `subscribe(listener)` | 이후 상태 변경 관찰, 구독 해제 함수 반환 |

복원 완료 전 편집은 기본적으로 충돌을 일으켜 복원을 중단합니다. 호출자가 정책을 선택하기 전에는 메모리나 저장값을 덮어쓰지 않습니다. **자동 깊은 병합은 없습니다.** 복원 성공 전 `flush()`는 확인하지 않은 저장값을 덮어쓰는 대신 거부됩니다.

쓰기는 직렬 실행됩니다. 하나의 쓰기가 실행되는 동안 대기 슬롯에는 최신 commit만 유지합니다. 실패한 쓰기는 대기 상태로 남고 새 commit이나 명시적 `flush()`로 재시도하며 무한 자동 재시도는 없습니다. `flush()`는 미래 편집을 끝없이 기다리거나 상태 debounce 타이머를 강제로 실행하지 않습니다. 성공한 `clearStorage()` 뒤에는 이전 대기 쓰기가 값을 되살리지 않으며 이후 사용자 commit은 다시 저장할 수 있습니다. 삭제로 대체된 대기 중 `flush()`는 `CLEARED`로 거부됩니다.

`saveDebounceMs?: number`는 전체 상태 설정과 projection 설정 모두에서 사용합니다. 생략하거나 `0`이면 기존 즉시 저장 동작을 유지합니다. `2147483647`밀리초 이하의 양의 유한 값을 지정하면 commit마다 저장 전용 타이머를 다시 시작합니다. 상태 변경이나 구독 알림은 지연하지 않으며 별도 `debounce()` 미들웨어나 순서 규칙도 바꾸지 않습니다.

`pause()`는 저장 타이머를 취소하고 최신 대기 상태를 유지합니다. 이미 시작한 쓰기와 대기 중인 flush 의무는 계속 진행됩니다. `flush()`와 `retry()`는 `paused`를 바꾸지 않고 일시 중지와 저장 타이머를 우회합니다. 성공한 복원이 선행되어야 하며, 캡처한 목표를 충족하기 위해 더 최신의 대체 값을 저장할 수 있습니다. 이후 commit이 완료된 목표를 연장하지 않습니다. `resume()`는 저장 대기 시간을 다시 시작하며 지연 설정이 없으면 즉시 저장합니다.

`clearStorage()`는 일시 중지되지 않습니다. 이전 대기 값과 타이머를 버리고 해당 flush Promise를 거부한 뒤 활성 쓰기 다음에 삭제를 수행합니다. 이후 쓰기는 삭제 장벽 뒤에 실행됩니다. dispose는 타이머를 취소하고 미완료 flush/retry를 `DISPOSED`로 거부합니다. 종료 후 동기 `pause()`와 `resume()`도 같은 오류를 던집니다. 저장이 필요하면 dispose 전에 flush하세요.

## 상태와 오류 관찰

`getStatus()`와 `subscribe()`가 `hasHydrated()`와 `onRehydrateStorage`를 대체합니다. 복원 상태는 `idle`, `hydrating`, `hydrated`, `conflict`, `error`이며 저장 상태는 `idle`, `writing`, `error`입니다. `pending`은 미저장 작업, `paused`는 자동 저장 일시 중지 여부, `disposed`는 영속화 종료 상태, `error`는 `PersistError` 또는 `null`입니다.

다음 코드는 앞의 `editor` 예제에 이어 사용합니다.

```ts lineNumbers
const unsubscribe = editor.persist.subscribe((status) => {
  if (status.error) {
    console.error(status.error.operation, status.error.code, status.error.cause);
  }
});
const status = editor.persist.getStatus();
const ready = status.hydration === 'hydrated';
unsubscribe();
```

오류는 `operation`, 안정적인 `code`, 원래의 `cause`를 제공합니다. 읽기, migration, decode, 검증 실패는 현재 상태를 유지합니다. commit 후 알림 실패는 commit을 롤백하거나 복원을 다시 적용할 이유가 되지 않습니다.

## 프레임워크 상태 바인딩

다섯 프레임워크 서브패스 모두 `bindPersistStatus(persist)`를 공개합니다.
상태 스토어 대신 `editor.persist`를 전달하세요. 매개변수는
`Pick<PersistControls, 'getStatus' | 'subscribe'>`이고 반환값은 해당 어댑터의
`UseReadonlyState<PersistStatus>`입니다. writer나 수명주기 제어는 노출하지 않습니다.
기존 selector와 선택적 equality 인수, Angular의 `{ destroyRef }` 옵션을
그대로 지원합니다. equality를 생략하면 어댑터의 얕은 비교를 사용하며 중첩
선택값에는 사용자 정의 equality를 전달할 수 있습니다.

앞의 `editor` 예제에 다음 React 컴포넌트를 추가하면 저장 상태를 표시합니다.

```ts lineNumbers
import { createElement } from 'react';
import { bindPersistStatus } from '@ilokesto/state/react';

const useEditorStatus = bindPersistStatus(editor.persist);

export function SaveStatus() {
  const status = useEditorStatus();
  const label = status.error ? '저장 실패'
    : status.hydration !== 'hydrated' ? '불러오는 중'
    : status.saving === 'writing' ? '저장 중'
    : status.pending ? '저장하지 않은 변경' : '저장됨';
  return createElement('output', { 'aria-live': 'polite' }, label);
}
```

다른 어댑터도 기존 readonly 반환 형태로 같은 상태를 제공합니다.

```ts
// Vue setup() 또는 effectScope():
const useStatus = bindPersistStatus(editor.persist); // @ilokesto/state/vue
const { state: saving } = useStatus(status => status.saving); // saving.value

// Angular 주입 컨텍스트 또는 소유한 DestroyRef 전달:
const useStatus = bindPersistStatus(editor.persist); // @ilokesto/state/angular
const { state: saving } = useStatus(status => status.saving, { destroyRef }); // saving()

// Solid 컴포넌트 또는 createRoot():
const useStatus = bindPersistStatus(editor.persist); // @ilokesto/state/solid
const { state: saving } = useStatus(status => status.saving); // saving()

// Svelte: 컴포넌트에서는 $saving, 수동 구독은 unsubscribe로 해제합니다.
const status = bindPersistStatus(editor.persist); // @ilokesto/state/svelte
const saving = status.select(snapshot => snapshot.saving);
```

각 코드는 독립된 조각이며 표시한 서브패스에서 `bindPersistStatus`를 가져옵니다.
전체 상태에는 `hydration`, `saving`, `pending`, `paused`, `disposed`, `error`가
포함됩니다. `binding.readOnly()`는 프레임워크 scope 밖에서도 항상 현재 상태를
읽습니다. React 서버 스냅샷은 바인딩 생성 시점의 상태이므로 SSR에서는 클라이언트
복원 전에 동일한 상태로 바인딩을 생성하세요.

바인딩 생성이나 `readOnly()` 호출만으로는 구독하지 않습니다. 각 활성 프레임워크
구독이 자신의 상태 연결과 registry-store selector 필터를 소유합니다.
언마운트, scope 정리, `DestroyRef`, Svelte unsubscribe가 해당 연결을 해제합니다.
같은 제어 객체에 여러 화면을 독립적으로 연결할 수 있습니다. 팩토리 수명의
연결을 별도로 정리할 필요가 없으며 화면 정리는 빌려 쓴 영속화나 상태 스토어를
종료하지 않습니다. 복원 시작, 거부된 작업 처리, flush, 스토어 정리는 계속
스토어 소유자의 책임입니다.

## SSR과 소유권

서버와 클라이언트에서 동일한 초기 상태를 사용하세요. 클라이언트 effect에서 `rehydrate()`를 시작하고 거부된 Promise를 처리합니다. 충돌 해결을 제공하지 않는 화면은 `getStatus().hydration === 'hydrated'`가 될 때까지 편집을 막으세요. 모든 전이를 관찰하도록 복원 시작 전에 구독합니다. `skipHydration` 옵션은 필요 없습니다.

스토어 소유자는 인스턴스가 더 필요 없을 때 `dispose(store)`를 호출합니다. 대기 작업을 취소하고 자신이 소유한 연결, 트랜잭션, 구독만 정리합니다. 두 스토어가 같은 팩토리를 사용해도 이 소유권은 공유하지 않습니다. 늦은 완료가 종료된 수명주기를 변경하지 못합니다. 정리는 저장 완료를 보장하거나 완료된 트랜잭션을 되돌리지 않습니다. 저장 보장이 필요하면 정리 **전에** `await store.persist.flush()`를 호출하세요.

## 미들웨어와 마이그레이션

영속화는 시도한 쓰기가 아닌 실제 commit을 관찰합니다. 검증에서 거절하거나 throttle이 버린 업데이트는 저장하지 않으며 지연된 commit과 재진입 commit은 저장합니다. 복원은 읽기, 저장 형식 검사, migration, decode, 설정된 경우 명시적 projection 복원, 등록된 상태 검증, 즉시 commit 순서입니다. debounce/throttle을 우회하고 상태 검증을 한 번만 실행하며 새 history 기준점이 됩니다. 복원 알림에서 발생한 사용자 편집은 정상 commit으로 저장됩니다.

`debounce()`는 `persist()`보다 먼저 선언하세요. 반대 순서는 계속 `MIDDLEWARE_ORDER`로 거부됩니다. `history()`와 `debounce()` 또는 `throttle()`의 기존 조합 제한은 유지됩니다.

모든 어댑터에 같은 migration 파이프라인이 적용됩니다. 데이터 버전은 migration 배열 길이이며 IndexedDB 스키마 버전, 내부 commit 순번과 구분합니다. 호환성 변경 표와 실행 가능한 예제는 [영속화 마이그레이션](/ko/state/advanced/persist-migrations)을 참고하세요.
