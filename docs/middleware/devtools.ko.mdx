# devtools

`devtools`는 store를 Redux DevTools browser extension과 연결합니다. 현재 state로 extension을 초기화하고, 실제로 반영된 update를 관찰하며, DevTools command를 처리합니다.

## Signature

```ts lineNumbers
devtools(name: string, options?: DevtoolsOptions): PipeAnyMiddleware
devtools(options: DevtoolsOptions & { readonly name: string }): PipeAnyMiddleware
```

## 예제

```ts lineNumbers
import { devtools, logger } from '@ilokesto/state/middleware';
import { pipe } from '@ilokesto/state/utils';

const store = pipe
  .use(devtools('counter'))
  .use(logger())
  .create({ count: 0 });
```

## 지원하는 DevTools action

| Command | State와 middleware 동작 |
| --- | --- |
| `RESET` | Store의 original initial state를 `setState`로 전달한 뒤 DevTools를 다시 초기화합니다. |
| `COMMIT` | Store를 변경하지 않고 현재 state로 DevTools를 다시 초기화합니다. |
| `ROLLBACK` | `message.state`를 decode하고 기존 middleware pipeline을 통해 반영합니다. |
| `JUMP_TO_STATE`, `JUMP_TO_ACTION` | `message.state`를 decode하고 검증한 뒤 즉시 교체하며, 로컬 undo/redo history를 비웁니다. |

Jump는 선택한 snapshot을 복원하며 reducer action을 실행하지 않습니다. State나 history baseline을 바꾸기 전에 등록된 `validate()` schema의 변환과 `onError` 계약을 적용합니다. `validate()`가 없으면 decode된 state를 그대로 받아들입니다. JSON parsing은 애플리케이션 schema 검증을 대신하지 않습니다.

성공한 jump는 subscriber와 persistence에 전달됩니다. 기존 persistence hydration/flush 계약에 따라 저장되지만 DevTools로 다시 전송되지는 않습니다. Jump의 subscriber에서 발생한 사용자 update는 정상적으로 관찰하고 저장합니다. 검증에 실패한 jump는 state와 history를 모두 유지합니다.

Jump는 reducer, debounce, throttle, logger를 포함한 일반 middleware를 우회합니다. 대기 중인 애플리케이션 update를 취소하지 않으므로 jump 이후 반영될 수 있습니다. `RESET`과 `ROLLBACK`은 timing middleware와 로컬 history 기록을 포함한 기존 동작을 유지하며, 동기적으로 반영된 값은 DevTools로 재전송하지 않습니다.

## 관찰과 payload

- Reducer dispatch는 원래 action의 필드와 payload를 보존하고 type에 이름을 붙여 전송합니다. 예: `{ type: 'counter:increment', payload: { amount: 2 } }`.
- 직접 변경은 기존 `counter:anonymous action` label을 유지합니다.
- Persistence 복원은 기존 `counter:persist/rehydrate` label을 유지합니다.
- 거부된 update나 동일한 state는 전송하지 않습니다. 중첩 dispatch도 각자의 payload와 commit snapshot을 유지합니다.

동기 dispatch 범위 밖에서 반영되는 지연되거나 합쳐진 commit은 하나의 활성 reducer action을 나타내지 않으므로 직접 변경 label을 사용합니다.

Label은 관찰용이며 persistence 형식이 아닙니다. `JUMP_TO_ACTION`도 표시된 payload를 다시 dispatch하지 않고 전달된 state를 복원합니다.

## 옵션

`DevtoolsOptions`, `DevtoolsAction`, `DevtoolsSerializeOptions`는 `@ilokesto/state/middleware`에서 export합니다.

| 옵션 | 계약 |
| --- | --- |
| `enabled` | `process.env.NODE_ENV === 'production'`이면 기본값은 `false`, 그 외에는 `true`입니다. 명시한 값이 기본값보다 우선합니다. |
| `stateSanitizer(state: unknown)` | 초기화, commit, persistence 복원에서 전송할 state를 반환합니다. |
| `actionSanitizer(action: DevtoolsAction)` | 전송할 action을 반환합니다. 기존 문자열 label 또는 reducer action 객체를 받습니다. |
| `serialize` | Redux DevTools 직렬화 설정을 `connect`에 전달합니다. Boolean 또는 `{ options, replacer, reviver }`를 받습니다. |
| `deserializeState(text: string)` | 복원 state를 동기적으로 decode합니다. 기본값은 `JSON.parse`이며, 지정된 `serialize.reviver`를 함께 적용합니다. |

```ts lineNumbers
import { devtools } from '@ilokesto/state/middleware';
import { pipe } from '@ilokesto/state/utils';

const store = pipe.use(devtools({
  name: 'session',
  stateSanitizer: (state) =>
    typeof state === 'object' && state !== null
      ? { ...state, token: '[redacted]' }
      : state,
  actionSanitizer: (action) =>
    typeof action === 'string' ? action : { type: action.type },
})).create({ token: 'private', count: 0 });
```

Sanitizer는 `structuredClone`으로 분리한 복사본을 받습니다. 입력을 직접 수정해도 store, initial state, dispatch payload는 변경되지 않습니다. 직렬화 옵션을 명시한 경우에도 extension 호출 전에 복사본을 만듭니다. 해당 옵션을 통과하는 값은 structured clone이 가능해야 합니다. 함수 등 지원하지 않는 값이면 해당 관찰 전송을 생략하고 `console.error`로 알리며, 이미 반영된 update는 되돌리지 않습니다. Sanitizer는 extension에 전달하지 않고 로컬에서 적용합니다.

직렬화 옵션은 DevTools 출력만 설정하며 persistence에는 영향을 주지 않습니다. `serialize: true`의 특수 값처럼 JSON이 아닌 extension encoding을 사용한다면 이에 맞는 `deserializeState`를 제공해야 합니다. 기본 parser는 Redux DevTools의 JSAN marker를 복원하지 않습니다. Sanitization은 가역 변환이 아니므로 민감한 값을 제거한 snapshot은 복원에 적합하지 않을 수 있으며, store의 validation schema에서 거부해야 합니다.

## 잘못된 메시지와 정리

Message는 문자열 `type`을 가진 객체여야 합니다. `DISPATCH`에는 문자열 `type`을 가진 `payload` 객체가 추가로 필요합니다. `ROLLBACK`과 두 jump command에는 문자열 `state`가 필요합니다. 잘못된 envelope는 `TypeError`, 잘못된 JSON은 `SyntaxError`를 state 변경 전에 발생시킵니다. Decoder와 validator의 예외도 호출자에게 전달합니다. 형식이 올바른 비-dispatch message와 알 수 없는 command 이름은 무시합니다.

`dispose(store)`는 해당 store의 commit observer와 extension listener 구독을 한 번만 해제합니다. 보관된 callback이나 이후의 write도 dispose 후에는 전송하거나 command를 적용하지 않습니다. 정리는 해당 store에만 적용하며, 다른 store까지 연결 해제할 수 있는 extension 전역 `disconnect()`는 호출하지 않습니다.

`window.__REDUX_DEVTOOLS_EXTENSION__`가 필요합니다. Browser나 extension이 없거나 `enabled: false`이면 연결하거나 state를 관찰하지 않습니다.
