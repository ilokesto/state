# Svelte

The Svelte adapter returns store objects that follow Svelte store expectations. Import from `@ilokesto/state/svelte`.

## Plain writable store

```svelte lineNumbers
<script lang="ts">
  import { create } from '@ilokesto/state/svelte';

  const counter = create({ count: 0, label: 'Clicks' });
  const count = counter.select((state) => state.count);
  const increment = () => counter.update((state) => ({ ...state, count: state.count + 1 }));
</script>

<button on:click={increment}>
  {$count}
</button>
```

Plain state is writable and includes `set`, `update`, `setState`, `select`, `writeOnly`, and `readOnly`.

## Reducer readable store

```svelte lineNumbers
<script lang="ts">
  import { create } from '@ilokesto/state/svelte';

  type Action = { type: 'increment' } | { type: 'reset' };
  
  const reduce = (state: { count: number }, action: Action) => {
    if (action.type === 'increment') return { count: state.count + 1 };
    if (action.type === 'reset') return { count: 0 };
    return state;
  };

  const counter = create(reduce, { count: 0 });
  const count = counter.select((state) => state.count);
</script>

<button on:click={() => counter.dispatch({ type: 'increment' })}>
  {$count}
</button>
```

Reducer state is readable because writes should go through `dispatch`.

## Outside component code

```ts lineNumbers
const current = counter.readOnly((state) => state.count);
const setCounter = counter.writeOnly();
setCounter((state) => ({ ...state, count: state.count + 1 }));
```

## Custom equality and readonly binding

Pass `equality(previous, next)` as the selector's second argument. Omitting it keeps the existing shallow comparison. The writers and result shapes from `create`, `bind`, and `bindReducer` stay unchanged.

`bindReadonly(source)` accepts a structural `ReadableStore<T>` and provides `Readable<ReadonlySnapshot<T>>` without a writer. `UseReadonlyState<T>` is exported from the same subpath. Use `readOnly()` for synchronous snapshots outside the lifecycle.

```ts lineNumbers
import type { ReadableStore } from '@ilokesto/store';
import { bindReadonly } from '@ilokesto/state/svelte';

declare const source: ReadableStore<{ count: number; label: string }>;
const useCounter = bindReadonly(source);
const select = (state: Readonly<{ count: number }>) => ({ nested: { count: state.count } });
const equality = (previous: ReturnType<typeof select>, next: ReturnType<typeof select>) =>
  previous.nested.count === next.nested.count;

const count = useCounter.select(select, equality);
const unsubscribe = count.subscribe(value => console.log(value.nested.count));
unsubscribe();
```

select(selector, equality?) immediately delivers the current value and subscribes independently per subscriber. Call unsubscribe to release it. Readonly bindings have no set/update/setState/dispatch/writeOnly.

Equality must be a pure equivalence relation. Returning true suppresses delivery and retains the previous selection. Equality does not apply to readOnly().

## Async resource store

`bindResource(resource)` returns `UseResource<Input, Output>`: a readonly Svelte store with `select`, `readOnly` and typed `run(input, options?)`. `$requestState` subscribes through the native Svelte lifecycle. `bindReadonly(resource.store)` is also available when no run helper is needed.

This component runs both success and failure without an API server:

```svelte lineNumbers
<script lang="ts">
  import { createResource } from '@ilokesto/state';
  import { bindResource } from '@ilokesto/state/svelte';

  const request = createResource(async (shouldFail: boolean) => {
    if (shouldFail) throw new Error('Try again');
    return 'Loaded';
  });
  const requestState = bindResource(request);
</script>

{#if $requestState.status === 'pending'}
  <p>Loading...</p>
{:else if $requestState.status === 'error'}
  <p>{String($requestState.error)}</p>
{:else if $requestState.status === 'success'}
  <p>{$requestState.data}</p>
{:else}
  <p>Choose an action</p>
{/if}
<button on:click={() => requestState.run(false)}>Load / retry</button>
<button on:click={() => requestState.run(true)}>Fail</button>
```

Retry starts another run. Unmount unsubscribes but never cancels a borrowed resource. A manual `subscribe` caller must call its returned unsubscribe function. Only the resource owner calls `cancel`/`dispose`; direct resource runs remain visible to subscribers. This is a Svelte store, not a React Suspense bridge.

## Caveats

- `subscribe` immediately calls the subscriber with current state, matching Svelte expectations.
- `select` creates a readable store for one projection.
- In reducer mode, prefer `dispatch`; direct writable methods are not exposed.
