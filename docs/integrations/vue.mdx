# Vue

Use the Vue adapter inside `setup()` or an active `effectScope`. Import from `@ilokesto/state/vue`.

## Plain state composable

Plain state returns `{ state: ComputedRef<S>, setState }`.

```ts lineNumbers
import { create } from '@ilokesto/state/vue';

const useCounter = create({ count: 0, label: 'Clicks' });

export default {
  setup() {
    const { state: count, setState } = useCounter((state) => state.count);
    const { state: label } = useCounter((state) => state.label);
    const increment = () => setState((prev) => ({ ...prev, count: prev.count + 1 }));

    return { count, label, increment };
  },
};
```

`state` is a `ComputedRef`, so templates unwrap it naturally while script code can read `state.value`.

## Reducer composable

```ts lineNumbers
import { create } from '@ilokesto/state/vue';

type Action = { type: 'increment' } | { type: 'reset' };

const reduce = (state: { count: number }, action: Action) => {
  if (action.type === 'increment') return { count: state.count + 1 };
  if (action.type === 'reset') return { count: 0 };
  return state;
};

const useCounter = create(reduce, { count: 0 });

export function useCounterActions() {
  const { state, dispatch } = useCounter((state) => state.count);
  const increment = () => dispatch({ type: 'increment' });
  return { count: state, increment };
}
```

## Outside Vue scope

Vue reactive calls intentionally throw outside `setup()`/`effectScope`. Use sync helpers for module code.

```ts lineNumbers
const count = useCounter.readOnly((state) => state.count);
const dispatch = useCounter.writeOnly();
dispatch({ type: 'reset' });
```

## Custom equality and readonly binding

Pass `equality(previous, next)` as the selector's second argument. Omitting it keeps the existing shallow comparison. The writers and result shapes from `create`, `bind`, and `bindReducer` stay unchanged.

`bindReadonly(source)` accepts a structural `ReadableStore<T>` and provides `{ state: ComputedRef<S> }` without a writer. `UseReadonlyState<T>` is exported from the same subpath. Use `readOnly()` for synchronous snapshots outside the lifecycle.

```ts lineNumbers
import type { ReadableStore } from '@ilokesto/store';
import { bindReadonly } from '@ilokesto/state/vue';

declare const source: ReadableStore<{ count: number; label: string }>;
const useCounter = bindReadonly(source);
const select = (state: Readonly<{ count: number }>) => ({ nested: { count: state.count } });
const equality = (previous: ReturnType<typeof select>, next: ReturnType<typeof select>) =>
  previous.nested.count === next.nested.count;

function useCount() {
  return useCounter(select, equality).state;
}
```

Call inside setup() or an active effectScope(), as before. Scope disposal unsubscribes, and equal selections retain the previous reference.

Equality must be a pure equivalence relation. Returning true suppresses delivery and retains the previous selection. Equality does not apply to readOnly().

## Async resource composable

`bindResource(resource)` returns `UseResource<Input, Output>`: the existing readonly composable plus a typed `run(input, options?)`. Call it in `setup` to get a `ComputedRef<ResourceState<Output>>`. Selectors and custom equality also work. For observation only, `bindReadonly(resource.store)` is equivalent.

This server-free example deliberately exposes success and failure actions:

```vue lineNumbers
<script setup lang="ts">
import { createResource } from '@ilokesto/state';
import { bindResource } from '@ilokesto/state/vue';

const request = createResource(async (shouldFail: boolean) => {
  if (shouldFail) throw new Error('Try again');
  return 'Loaded';
});
const useRequest = bindResource(request);
const { state } = useRequest();
</script>

<template>
  <p v-if="state.status === 'pending'">Loading...</p>
  <p v-else-if="state.status === 'error'">{{ String(state.error) }}</p>
  <p v-else-if="state.status === 'success'">{{ state.data }}</p>
  <p v-else>Choose an action</p>
  <button @click="useRequest.run(false)">Load / retry</button>
  <button @click="useRequest.run(true)">Fail</button>
</template>
```

Retry calls `run` again. Vue scope disposal removes its subscription without cancelling work; a shared resource may continue serving other components. Creating the binding does not start or own the resource. Only its owner calls `cancel`/`dispose`. Runs started directly on the resource remain observable. There is no React Suspense behavior in this composable.

## Caveats

- Reactive reads require `getCurrentScope()` to exist.
- Cleanup is registered with `onScopeDispose`, so do not bypass Vue scope for subscribed reads.
- Use `readOnly()` for one-time reads; it is not reactive.
