# React

Use the React adapter when a React component needs a subscribed value from an `@ilokesto/store`-backed state container. Import from `@ilokesto/state/react`, not from the root package.

## Adapter types

`UseState` and `UseReducer` describe the hooks returned by the plain-state and reducer `create()` overloads. Import them from the same React subpath when a public API accepts either hook type.

```ts lineNumbers
import type { UseReducer, UseState } from '@ilokesto/state/react';
```

## Plain state hook

Plain state returns the same shape as a small React state hook: `[selection, setState]`.

```tsx lineNumbers
import { create } from '@ilokesto/state/react';

type CounterState = { count: number; label: string };

const useCounter = create<CounterState>({ count: 0, label: 'Clicks' });

export function CounterButton() {
  const [count, setCounter] = useCounter((state) => state.count);
  const [label] = useCounter((state) => state.label);

  return (
    <button onClick={() => setCounter((prev) => ({ ...prev, count: prev.count + 1 }))}>
      {label}: {count}
    </button>
  );
}
```

The selector decides the value returned as the first tuple item. The writer still updates the full state, so keep object updates immutable.

## Reducer hook

Reducer state uses the same `create(reduce, initialState)` overload. The tuple writer becomes `dispatch`.

```tsx lineNumbers
import { create } from '@ilokesto/state/react';

type Action = { type: 'increment' } | { type: 'reset' };

const reduce = (state: { count: number }, action: Action) => {
  if (action.type === 'increment') return { count: state.count + 1 };
  if (action.type === 'reset') return { count: 0 };
  return state;
};

const useCounter = create(reduce, { count: 0 });

function ReducerCounter() {
  const [count, dispatch] = useCounter((state) => state.count);
  return <button onClick={() => dispatch({ type: 'increment' })}>{count}</button>;
}
```

## Outside React lifecycle

`readOnly()` and `writeOnly()` are attached to the hook function. Use them in modules, service callbacks, tests, or event buses that should not call a hook.

```ts lineNumbers
const readCount = useCounter.readOnly((state) => state.count);
const dispatch = useCounter.writeOnly();
dispatch({ type: 'reset' });
```

## Custom equality and readonly binding

Pass `equality(previous, next)` as the selector's second argument. Omitting it keeps the existing shallow comparison. The writers and result shapes from `create`, `bind`, and `bindReducer` stay unchanged.

`bindReadonly(source)` accepts a structural `ReadableStore<T>` and provides `S` without a writer. `UseReadonlyState<T>` is exported from the same subpath. Use `readOnly()` for synchronous snapshots outside the lifecycle.

```ts lineNumbers
import type { ReadableStore } from '@ilokesto/store';
import { bindReadonly } from '@ilokesto/state/react';

declare const source: ReadableStore<{ count: number; label: string }>;
const useCounter = bindReadonly(source);
const select = (state: Readonly<{ count: number }>) => ({ nested: { count: state.count } });
const equality = (previous: ReturnType<typeof select>, next: ReturnType<typeof select>) =>
  previous.nested.count === next.nested.count;

function useCount() {
  return useCounter(select, equality);
}
```

React uses the same equality for subscription filtering and client/server snapshot stabilization. Replacing the selector or equality resubscribes with the new function. Hook rules and StrictMode cleanup still apply.

Equality must be a pure equivalence relation. Returning true suppresses delivery and retains the previous selection. Equality does not apply to readOnly().

## Async resources and optional Suspense

`bindResource(resource)` returns `UseResource<Input, Output>`: the readonly hook (including selectors and `readOnly`) plus `run(input, options?)` and `useSuspense()`. A normal `useRequest()` returns every `ResourceState` variant and can observe work started anywhere. `bindReadonly(resource.store)` remains sufficient when you only need observation.

`useSuspense()` returns `idle` or `success`, throws the original error to an error boundary, and suspends only for pending work started through **this binding's `run`**. Create the binding once and share it. Start work in an event or service, never during render. The returned run promise is the stable Suspense promise for that execution; a new run replaces it. A pre-aborted run does not replace active work.

The example intentionally offers a failing action so loading, error and retry are all executable without a server:

```tsx lineNumbers
import { Component, Suspense, useState, type ReactNode } from 'react';
import { createResource } from '@ilokesto/state';
import { bindResource } from '@ilokesto/state/react';

const request = createResource(async (shouldFail: boolean) => {
  if (shouldFail) throw new Error('Try again');
  return 'Loaded';
});
const useRequest = bindResource(request);

class RequestBoundary extends Component<{ children: ReactNode }, { failed: boolean }> {
  state = { failed: false };
  static getDerivedStateFromError() { return { failed: true }; }
  render() { return this.state.failed ? <p>Request failed. Retry below.</p> : this.props.children; }
}

function Result() {
  const state = useRequest.useSuspense();
  return <p>{state.status === 'success' ? state.data : 'Choose an action'}</p>;
}

export function ResourcePanel() {
  const [attempt, setAttempt] = useState(0);
  const load = (shouldFail: boolean) => {
    void useRequest.run(shouldFail);
    setAttempt(previous => previous + 1);
  };
  return (
    <section>
      <RequestBoundary key={attempt}>
        <Suspense fallback={<p>Loading...</p>}><Result /></Suspense>
      </RequestBoundary>
      <button onClick={() => load(false)}>Load / retry</button>
      <button onClick={() => load(true)}>Fail</button>
    </section>
  );
}
```

Retry explicitly starts a new run and resets the boundary; resetting the boundary alone does not retry. Cancelling or disposing pending work returns `idle`, never a permanent suspension. Disposal after completion retains the terminal snapshot, just like the neutral resource. A pending run started directly through `request.run` (or another binding) produces a descriptive error in `useSuspense`; use the normal hook for that integration. This avoids subscribing during an uncommitted render. Unmount, including an abandoned suspended mount, releases only React's subscription: it never cancels a borrowed resource. The resource owner alone decides when to call `cancel` or `dispose`.

The Suspense helper uses the existing initial-state server snapshot (`idle`); it does not start server work or provide a server data cache.

## Caveats

- The returned function is a React hook because it uses `useSyncExternalStore`; call it only inside components or custom hooks.
- `getServerSnapshot` starts from the store initial state, so SSR hydration should use the same initial state on server and client.
- Selectors should be pure and cheap. React memoizes snapshots, but expensive selectors still run during render/snapshot work.
